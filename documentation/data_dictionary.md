# E-Commerce Sales Data Warehouse
## Gold Layer — Data Dictionary

## 1. Project Overview

This document describes the five analytical tables created in the Gold layer of the E-Commerce Sales Data Warehouse.

**Database:** `MY_FIRST_DB`
**Schema:** `GOLD`
**Dataset period:** October 1–31, 2019
**Data source:** REES46 E-Commerce Behavior Dataset

The Gold layer contains business-oriented datasets designed for sales analysis, product performance analysis, customer behavior analysis, and conversion funnel analysis.

---

## 2. Gold Layer Tables

| Table | Grain | Purpose |
|---|---|---|
| `DAILY_SALES` | One row per calendar day | Daily sales and purchase-event analysis |
| `PRODUCT_PERFORMANCE` | One row per product | Product engagement and purchase-event performance |
| `CUSTOMER_BEHAVIOR` | One row per user | Customer activity and behavioral analysis |
| `CONVERSION_FUNNEL` | One aggregate row | Session-level event co-occurrence analysis |
| `CONVERSION_FUNNEL_SEQUENTIAL` | One aggregate row | Session-level sequential conversion analysis |

---

## 3. DAILY_SALES

**Purpose:** Provides daily aggregated purchase-event metrics.

**Grain:** One row per sales date.

| Column | Description |
|---|---|
| `SALES_DATE` | Calendar date associated with the aggregated events |
| `TOTAL_PURCHASE_EVENTS` | Total number of purchase events recorded on that date |
| `TOTAL_REVENUE` | Sum of product prices associated with purchase events; a revenue proxy, not verified paid revenue |
| `UNIQUE_BUYERS` | Distinct users generating purchase events on that date |
| `PURCHASE_SESSIONS` | Distinct sessions containing purchase events |
| `AVG_PURCHASE_VALUE` | Average price associated with purchase events, based on the underlying aggregation |

**Expected row count:** 31

---

## 4. PRODUCT_PERFORMANCE

**Purpose:** Measures product-level engagement and purchase-event performance.

**Grain:** One row per product.

| Column | Description |
|---|---|
| `PRODUCT_ID` | Unique product identifier |
| `CATEGORY_ID` | Product category identifier |
| `CATEGORY_CODE` | Product category classification |
| `BRAND` | Selected brand value associated with the product |
| `BRAND_CONFLICT_FLAG` | Indicates whether inconsistent brand values were observed for the product |
| `TOTAL_VIEWS` | Total view events for the product |
| `TOTAL_CART_EVENTS` | Total cart events for the product |
| `TOTAL_PURCHASE_EVENTS` | Total purchase events for the product |
| `TOTAL_REVENUE` | Sum of prices associated with purchase events; a revenue proxy |
| `UNIQUE_USERS` | Number of distinct users interacting with the product |

**Expected row count:** 166,794

**Data quality note:** 137 products had conflicting brand values. The selected brand is a deterministic alphabetical choice, not an authoritative resolution.

## 5. CUSTOMER_BEHAVIOR

**Purpose:** Provides user-level behavioral metrics across the observed dataset period.

**Grain:** One row per user.

| Column | Description |
|---|---|
| `USER_ID` | Unique user identifier |
| `TOTAL_EVENTS` | Total recorded events generated by the user |
| `TOTAL_VIEWS` | Number of view events |
| `TOTAL_CART_EVENTS` | Number of cart events |
| `TOTAL_PURCHASE_EVENTS` | Number of purchase events |
| `TOTAL_REVENUE` | Sum of prices associated with the user's purchase events; a revenue proxy |
| `UNIQUE_PRODUCTS_INTERACTED` | Number of distinct products interacted with |
| `UNIQUE_CATEGORIES_INTERACTED` | Number of distinct categories interacted with |
| `TOTAL_SESSIONS` | Number of distinct sessions associated with the user |
| `FIRST_EVENT_TIME` | Earliest observed event timestamp for the user |
| `LAST_EVENT_TIME` | Latest observed event timestamp for the user |

**Expected row count:** 3,022,290

**Interpretation note:** First and last event timestamps represent observed activity in this dataset. They are not customer registration dates or account creation dates.

## 6. CONVERSION_FUNNEL

**Purpose:** Measures session-level event co-occurrence without requiring chronological event ordering.

**Grain:** One aggregate row for the complete dataset period.

| Column | Description |
|---|---|
| `TOTAL_SESSIONS_ANALYZED` | Total distinct sessions analyzed |
| `SESSIONS_WITH_VIEW` | Sessions containing at least one view event |
| `SESSIONS_WITH_CART` | Sessions containing at least one cart event |
| `SESSIONS_WITH_PURCHASE` | Sessions containing at least one purchase event |
| `SESSIONS_WITH_VIEW_AND_CART` | Sessions containing both view and cart events |
| `SESSIONS_COMPLETING_FUNNEL` | Sessions containing view, cart, and purchase events |
| `VIEW_TO_CART_RATE` | Percentage of view sessions that also contain cart events |
| `CART_TO_PURCHASE_RATE` | Percentage of view-and-cart sessions that also contain purchase events |
| `VIEW_TO_PURCHASE_RATE` | Percentage of view sessions that also contain purchase events |

**Important:** This is a co-occurrence funnel. It does not establish whether the events happened in the expected chronological order.

---

## 7. CONVERSION_FUNNEL_SEQUENTIAL

**Purpose:** Measures conversion using event timestamp ordering.

**Grain:** One aggregate row for the complete dataset period.

| Column | Description |
|---|---|
| `TOTAL_SESSIONS_ANALYZED` | Total distinct sessions analyzed |
| `SESSIONS_WITH_VIEW` | Sessions containing view events |
| `SESSIONS_WITH_VIEW_THEN_CART` | Sessions with a view followed by a cart event |
| `SESSIONS_COMPLETING_SEQUENTIAL_FUNNEL` | Sessions with view, followed by cart, followed by purchase |
| `VIEW_TO_CART_RATE` | Percentage of view sessions progressing to a subsequent cart event |
| `CART_TO_PURCHASE_RATE` | Percentage of qualifying view-then-cart sessions progressing to purchase |
| `VIEW_TO_PURCHASE_RATE` | Percentage of view sessions completing the sequential funnel |

**Important limitations:**

- Sequential ordering uses event timestamps.
- The source data has second-level timestamp precision and no unique event sequence identifier.
- Events occurring in the same second cannot be reliably ordered.
- The funnel is session-level; cart and purchase events may involve different products within the same session.

## 8. Metric Interpretation and Business Caveats

### Revenue

`TOTAL_REVENUE` is calculated using prices associated with purchase events.

It should be interpreted as a **purchase-event revenue proxy**, not verified financial revenue.

The dataset does not provide a verified order ID or payment transaction ID to establish completed paid transactions.

### Purchase Events

A purchase event is a recorded event type in the source dataset. It should not automatically be interpreted as a unique order or payment.

### Conversion Rates

The standard and sequential funnels use different methodologies. Their results should be compared as methodology-specific metrics, not treated as identical measurements.

### Dataset Scope

- The analysis covers October 2019 only.
- The dataset represents recorded e-commerce behavior events.
- Metrics reflect the available source data and its limitations.
